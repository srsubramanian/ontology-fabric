    Arrive

    Every question arrives as a tool call and is checked before anything is searched. The caller’s identity is also mapped to what each store will let them see.

    • The gateway checks who is asking and whether they may call this tool
    • Clearance becomes an OpenSearch filter and a read-only Snowflake role
    • One ontology version is pinned for the whole answer

    Understand
    A small Claude call reads the question with the ontology’s terms beside it, and splits it into sub-questions, one per store that can answer it.
    
  
    
  
    • It spots names, business terms, time words and “why” questions
    • Each sub-question gets a route: warehouse, graph, text or code
    • Defaults, like the merchant’s region, are recorded so the answer can state them

    3
    Entry points
    Every thing the question names becomes one ID, and that one ID opens all three stores.
    
  
    
  
    • Names go through hybrid search, with fuzzy matching and the ontology’s aliases
    • Business terms, like VAMP, resolve to ontology concepts
    • One ID rule, set in the ontology, links Neptune, Snowflake and OpenSearch

    4
    Walk the graph
    To answer “what drove it”, Neptune follows the cards behind August’s fraud reports to see where else they were used.
    
  
    
  
    • The walk starts from the merchant’s ID, never from a scan
    • It follows only the relationships this pattern needs
    • Limits come from the template: 4 hops, 500 nodes, 3 seconds
    
  
    
    
    
    
    Arrows fold in two hops each: card to authorization to merchant. Red means the authorization carries a fraud report. Four of 214 cards shown.
    
    
    
  
    

    


    
  
    5
    Count in the graph
    Some counts follow relationships. Those belong in Neptune; sums over huge tables belong in the warehouse.
    
  
    
  
    • If the count follows relationships, ask Neptune
    • If it sums or averages over huge tables or time, ask Snowflake
    • Common counts run reviewed templates; new ones get checked Cypher
    
  
    
    
    
      
    Neptunecounts along relationships“How many of these fraud reports are on cards also reported elsewhere?”
    
      
    Snowflakesums over big tables and time“What share of August’s transactions were reported or disputed?”
    
      
    OpenSearchfinds and ranks text“What does Visa say the threshold is?”

    6
    Ask the warehouse
    Snowflake holds every transaction. It answers “how much” and “how often”, using a metric the ontology defines once.
    
  
    
  
    • The metric is defined once in the ontology and generated into Snowflake
    • The ratio is computed in SQL, never by the model
    • Snowflake’s own role and row policies decide what the caller sees

    7
    Find the text
    The rules and runbooks say what the numbers mean. Four passes pick the few passages worth reading.
    
  
    
  
    • Hybrid search over chunks, with the caller’s clearance as a filter
    • Chunks that mention the resolved entities or concepts get a boost
    • A reranking model keeps the best three, and drops the wrong network

    8
    Assemble
    Results from all three stores, plus the ontology’s definitions, are packed into one context. Everything carries the ID Claude will cite.
    
  
    
  
    • Each store’s results arrive tagged with query or document IDs
    • Data freshness travels with the warehouse numbers
    • A token budget keeps it focused; the lowest-ranked items go first

    Answer
    Claude writes only from the context, and every sentence cites the store and ID it rests on.
    
  
    
  
    • Numbers come from the warehouse, reasons from the graph, rules from the text
    • Every sentence carries the IDs it rests on
    • Freshness and defaults are stated, not assumed

    10
    Check
    Before the answer leaves, code checks it against every store’s results. Claude isn’t trusted to check itself.
    
  
    
  
    • Every number must match a query result from Snowflake or Neptune
    • The threshold must match the rules passage for the merchant’s region
    • Freshness must be stated, and the caller must be allowed to see every source
    
  
    
    
    
      
    Every cited ID is in the context package
    
      
    Every number matches a query result
    
      
    The threshold matches the rules for a US merchant
    
      
    Data freshness is stated
    
      
    The caller may see every cited source

    11
    Watch and improve
    Every answer leaves a trace. Time, cost and quality are measured per stage, and failures become tests.
    
  
    
  
    • The four lanes run in parallel, so the slowest one sets the pace
    • Snowflake is the slowest lane; cached results and monthly aggregates help
    • Every failure becomes a new competency question

    Closing the loop. A wrong match, a rejected query, a number that doesn’t reconcile, or an unanswered question is saved with its trace, added to the competency questions, and, if the ontology lacked a term, turned into a proposal for the ontology’s change loop.
